# unagi-kc-audit

Audit code and released toolkit for the manuscript **"Gene-regulatory priors do not reach
the loss: a dual-spectrum audit of single-cell variational autoencoders."**

The question this repository answers: *did the injected prior actually reach the training
objective?* A prior can be built, stored, and never read. That is not hypothetical here — it
is what the audit found in the pipeline it examines. Most of the code exists to make that
claim checkable rather than rhetorical.

---

## The released toolkit

`kappa_c_audit/` is a dependency-light Python package (numpy, h5py) implementing four checks:

| Check | Question |
|---|---|
| `gradient_check` | does the spectral response track the prior gradient? |
| `prior_strength_scan` | is the collapse invariant to prior strength? |
| `structural_bound` | is the compression even feasible? |
| **`injection_path_check`** | **did the prior reach the loss?** |

The fourth is the one the paper turns on, and it can be pointed at **your own** pipeline:

```bash
pip install kappa-c-audit h5py
python examples/check_injection_path.py \
    --artifacts /path/to/saved_training_outputs \
    --source    /path/to/your/training/code
# exit 0 = not blocked, 1 = BLOCKED, 2 = could not run
```

Full walkthrough, including where the check can mislead you:
[`kappa_c_audit/docs/RUN_THE_INJECTION_PATH_CHECK.md`](kappa_c_audit/docs/RUN_THE_INJECTION_PATH_CHECK.md).

```bash
python -m pytest kappa_c_audit/tests -q     # both outcomes are covered
```

## Layout

| Path | What it holds |
|---|---|
| `kappa_c_audit/` | the released package: checks, tests, worked examples |
| `code/` | analysis and audit scripts |
| `figures/` | one generator per manuscript figure |
| `tools/` | the gating suite that validates the manuscript |
| `data/` | derived result files (JSON/CSV), one per reported number |
| `manuscript/` | LaTeX sources for the paper and its Supplementary Information |
| `reports/` | audit records: how each number was verified, and what is _not_ proven |

`reports/PAPER1_FULL_AUDIT_20261008.md` is the substantive one: it records the provenance
of every claim, and states explicitly which claims cannot be traced to a retained artefact.

## Reproducing

```bash
python -m pip install -r requirements.txt          # numpy, pandas, matplotlib, h5py, scipy
python tools/run_checks.py --strict                # the gating suite
python code/kappa_c_pr_comparison.py               # regenerate the main kappa-C comparison
python figures/make_fig_crossarch_paired.py        # regenerate a figure
```

The gating suite covers text integrity, citations, numerical claims against their artefacts,
the raw-output manifest, and every build log. It exits non-zero on any gating failure.

**Derived results only.** The raw training artefacts (~39 GB of stagedata) are not included:
they derive from public data and are regenerated by the released code.

## Data

All datasets are public: GSE150774 (haematopoietic), GSE136831 (*IPF Cell Atlas* — see
[Adams et al. 2020](https://doi.org/10.1126/sciadv.aba1983)), GSE153162 (mouse cortex), and
the GEARS benchmark. Source publications for each accession are cited in the Methods.

---

## Two things worth stating plainly

1. **The audit is specific to an implementation.** Finding that this pipeline never
   delivered its prior says nothing about GRN priors in general. The code repeats this in
   its own output so a result cannot be over-read.
2. **The `injection_path_check` verdict is decisive in one direction only.** A `BLOCKED`
   result is proved by the artefacts. A passing result says the prior *arrived* — not that
   it is effective.
